# 检索指南（无 dsh tool 时的 fallback 流程）

## 环境

- vault：项目根 `.wiki/`（纯 Markdown）
- 可用工具：grep / glob / read（内置），无需插件工具
- 分层原则：先便宜后贵；L1 命中后仍继续 L2 核对更强者（等价于工具 auto 模式从 L2 开始），L2 命中即停

## 分层步骤

1. **L1（index 快速层）**：读 `.wiki/index.md`，匹配查询词所在行。auto 模式下这是预热扫描，
   命中后继续 L2 核对更强者，不要命中即停；仅显式 index-only 快速路径才在 L1 命中即止
   （等价于 `wiki_query` 工具 `mode=index-only`）。
2. **L2（标题/标签层）**：`grep -rli "<query>" .wiki --include="*.md"` 得到文件列表，
   逐个读 frontmatter 的 title/tags/summary 与查询词比对。
   **摘要层严格低于正文层**：只有当查询出现在 `summary` 里、却不在该页标题/标签/正文里时，
   摘要才算独立命中（派生摘要等同正文首行，必然走不到这一层）。所以摘要要与正文用不同措辞
   才有检索价值。
3. **L3（正文层）**：对 L2 候选打开正文，定位查询词，截取上下文 ≤200 字符。
4. **L4（图谱层）**：解析命中页的 `[[wikilink]]`，取一跳邻居补充关联候选。

## 有工具时：语义种子 + 双链下钻（优先）

上面的 L1–L4 是**词面**流程，改写式提问（「怎么避免定时器在错误的时钟下工作」）必然 0 命中。
只要环境里有插件工具，这类提问**优先走 `wiki_drill`**：

1. `wiki_drill({ query })` —— 语义（QMD 本地向量 + BM25）与词面两路按名次 RRF 融合出**种子页**，
   每个种子附带**一跳**双链邻居（`direction` 出/入、`broken` 断链、`via` 来源种子）。
2. `wiki_read({ id })` —— 读**整页**正文 + frontmatter 摘要 + 出/入链清单。
   **引用前必须读整页**：只用 snippet 合成答案会产出「有引用格式、没读原文」的伪知识。
3. 需要更深就 `wiki_drill({ page: '<上一页链到的 id>' })` **逐跳**推进——工具刻意只给一跳
   （实测两跳即覆盖全库 40%–60%），走哪条链由调用方决定。

手工等价做法（无工具）：
- 语义种子：无法用 grep 复现（需要嵌入模型），只能改用「读 `index.md` 全表 + 逐个读 summary」近似；
- 双链下钻：对已命中的页 `grep -o "\[\[[^]]*\]\]" <页文件>` 取出链，逐个 `read` 一跳邻居；
  入链则需 `grep -rl "\[\[<id>\]\]" .wiki` 反查。
- 邻居不是命中：顺链找到的页要注明「关联」，证据强度低于直接命中（与工具里
  `matchedBy: 'graph-neighbor'` 同一口径）。

## 排序（无工具时的近似）

插件工具的候选自带 `score` 且已降序；纯 grep fallback 没有分数，按同一口径手工近似：

1. 先按命中层：标题精确 > 标题 > 标签 > 摘要 > 正文 > 图谱邻居
2. 同层按度（该页 wikilink 出链 + 入链条数）降序
3. 仍相同按 `tier`（core > supporting > peripheral），最后按页面路径

即 `(基础分 + min(度 × 0.1, 2)) × tier 权重`，基础分取值见 `SKILL.md` 的打分表。

## 降级路径

- 没有 grep（受限环境）：用 read 逐文件读 `listPages` 等价目录清单，逐个比对标题。
- index.md 不存在：跳过 L1 直接从 L2 开始。
- 查询词过宽（命中 >20 文件）：取前 10 个相关性最高的，注明「结果过多已截断」。

## 答案规范

- 每条引用格式：`页面路径（confidence: extracted|inferred|ambiguous）`
- 尽量同时给出命中层或分数（如 `score 6.0 / 标题命中`），便于判断证据强弱
- 引用必须来自真实读到的文件，不得编造。

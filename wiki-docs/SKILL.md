# Wiki Docs — 项目文档提炼进知识库

把项目里的**文档内容**（不是代码结构、不是会话）蒸馏成知识页入库。与另外两条采集通道互补：
wiki-collect 挖"系统由什么构成"（代码结构），wiki-distill 蒸"发生了什么"（会话），
wiki-docs 收"项目自己写了什么"（文档与说明）。

**授权与写入规则（单一规则，不得自行放宽或加严）**：
1. 授权 = 用户显式触发（GUI 启动器点击，或在对话里明确要求）；
2. 入库前**必须**先调 `wiki_checkpoint` 建还原点，并先输出**写前清单**（将创建/更新哪些页：id、category、理由、来源）；
3. 写前清单是**信息性预览**：列完即继续 `wiki_ingest` 入库，**不等待确认回复、不做阻塞式二次确认**（用户可随时打断；质量不佳可用还原点整库回滚）；
4. 收尾**必须**输出质量评估报告（还原点 id、页清单、查重决策、风险项）；
5. 知识库将来纳入 git 分支合并把关（预留，未实现）。

扫描只读；写入一律经 `wiki_ingest`；不得绕过第 2 步直接写入。

## 第 0 步：确认范围（必做）

- 目标 = 用户给定的路径或通配（相对当前工作区/库根），如 `docs/`、`README.md`、`docs/**/*.md`
- 未给路径时**先向用户要范围**，不要擅自全库扫描——文档蒸馏的对象必须由用户圈定
- 先盘点候选文件并报数（逐个列出路径与格式）；二进制格式（pdf / 图片 / docx / xlsx 等）
  **明确声明不支持**，不做 OCR、不做解包解析；超大文件（>1MB）建议拆主题分批
- 大目录分批（单批 ≤20 文件），先蒸用户点名的核心文档

## 第 1 步：通读 + 查重（联动存量知识）

- 逐文件通读（read/glob 只读），提炼**可复用的结论与事实**——不是抄目录、不是整段搬运原文
- 对每个候选主题页先 `wiki_query` 查同名/近似页：已有 → 更新该页（保留 created），确实没有 → 才新建
- 源文件只读；不读 `.dsh/` 会话归档、`.wiki/_system/`、`node_modules/`、`.git/` 等非文档源

## 第 2 步：蒸馏（模型工作）

1. 按主题组织页面：单文档结论一页（category=references，来源 = 该文件）；
   跨多个文档的综合结论单独成页（category=synthesis，正文列出全部来源文件）
2. 页面正文：结论优先；关键数字 / 路径 / 命令保留原文；每页标注来源（文件路径 + 小节或行号）
3. 文档之间相互矛盾时如实并陈并标 `inferred`，不得擅自裁决成事实
4. 过时内容照录并标注其版本/时间语境，不替文档"更新"它没说的事

## 第 3 步：入库（wiki_ingest）

- 前置：已按「授权与写入规则」创建还原点并输出写前清单（清单为信息性预览，不阻塞）
- source = `file:<相对路径>`（跨文档综合页取主来源 `file:<主来源>`，正文里列全其余来源）
- contentHash = **源文件字节的 SHA-256**：文件未变 → 重跑自动跳过，天然幂等；文件变了 → 对账后更新本页
- confidence = 文档明说的事实用 `extracted`；跨文档归纳 / 矛盾裁决用 `inferred`；不得把推断写成事实
- 不覆盖他源页面：库内已有他源同 id 页由 wiki_ingest 自动 `-2` 避让，不得覆盖

## 第 4 步：收尾

- 建议用户「重建索引」让 index.md 覆盖新增页
- 报告：`本批 N 文件 → 入库 X 页（新建 A / 更新 B）/ 跳过 Y（哈希未变或库内已有）/ 不支持 Z（逐个列明格式与原因）`

## 范围边界（不得逾越）

- 仅处理文本可读内容：Markdown / txt / rst / adoc / 源码内注释文档等；
  二进制格式（pdf / 图片 / office 文档）不支持，不得声称解析过它们
- 文档蒸馏的对象必须由用户圈定；不得借"顺手"扩大到未点名的目录
- 只读工作区文件；不得读取 .dsh 会话归档/日志等非文档源
- 库内已有他源页面同 id 时由 wiki_ingest 自动 `-2` 避让，不得覆盖
